## What is missing (found while reading)

1. **No per-tenant cost circuit breaker exists at all.** Section 7.9 calls for one
   and 7.16.2 depends on it, but no code reads a daily cost. 5.7 must build the
   minimum version (see 3 below). It is the biggest item beyond the spec's
   wording.
2. **The web upload endpoint has no ceiling check.** Only email intake can
   quarantine today. The ceilings must apply to uploads too.
3. **Metering counts linked duplicates.** The Console query excludes test-batch,
   failed and quarantined, but not documents linked as duplicates
   (`duplicate_of_document_id`), which 7.16.1 says count once.
4. **No release, clear, or rotate function exists.**
5. **A `grace` intake address gets a bare 404** from the intake router (only
   `active` is accepted), so the required "this address has changed" auto-reply
   can't happen yet.
6. **"Known sender" ignores buyers.** D-031 deferred matching a sender's
   address or domain against buyer records until buyers existed. They exist now.
7. **No tenant-facing screens exist** beyond review. The banner and "Held for
   review" section have nowhere to live yet (see the 5.8 split).

## Proposed build, in order

### A. Metering (one definition)
- New `docflow_core/usage.py`: `month_usage(tenant_id)` = documents this
  calendar month in the tenant's timezone, `NOT is_test_batch`, status not in
  (`failed`, `quarantined`), `duplicate_of_document_id IS NULL`, not deleted.
- The Console tenant-list query gets the duplicate exclusion, and a test
  asserts both give the same number for a seeded tenant (prevents drift).

### B. Thresholds: banners, emails, alert (7.16.1)
- New table `allowance_notices` (tenant_id, month, threshold), unique on the
  three, so "one email per threshold per month" is enforced by the database.
- Checked when a document is counted (after ingest) using the constants
  0.8 and 1.0. At each threshold: owner email via the outbox (new templates),
  and at 100% an `allowance_reached` alert, severity info.
- Banner text comes from the catalog (`LIM-001` at 80%, `LIM-002` at 100%)
  and names the number, the tier and the next tier's allowance.
- Documents are never blocked, delayed or degraded by the allowance.

### C. Abuse ceilings and the cost breaker (7.16.2, 7.9)
- One function `intake_gate(tenant_id)` used by both email intake and the
  upload endpoint. It returns a quarantine reason or none:
  1. month's received documents (excluding test batch) at or above
     `ABUSE_CEILING_MULTIPLIER` × allowance → `abuse_ceiling`
  2. today's AI cost or tokens at or above the daily ceiling → `cost_breaker`
- **Stateless by design:** it is recomputed on each arrival, so there is no
  "paused" flag to get stuck. Alerts still fire once (existing dedupe).
- New constants for the daily ceilings (values: see question 1).
- Tripping: document stored as `quarantined`, never sent to the model; email
  intake auto-replies "received and held" (new catalog code); alert severity
  high; tenant banner. Documents already processing finish normally.

### D. Release, clear, retention (7.16.4)
- Migration `0021`: `documents.released_at`, `released_by_user_id`,
  `released_acting_as_tenant_id`; `intake_addresses.grace_ends_at`;
  `tenants.strict_sender_mode` and `tenants.sender_allowlist`.
- `quarantine.release(document_ids)` moves documents to `pending` and enqueues
  them **in received order** (`created_at`). Released documents then count
  against the allowance because their status is no longer `quarantined`.
- Permissions enforced in the API, not the UI: tenant owner may release
  `attachment_cap` and `unknown_sender_velocity`; only the founder may release
  `abuse_ceiling`, `cost_breaker`, `auth_fail`.
- A founder release ignores a still-tripped ceiling (an explicit human act);
  the alert says so.
- Clear = soft-delete (`deleted_at`), type-to-confirm, `admin_actions` row.
- Documents past `QUARANTINE_TTL_DAYS` raise an attention-panel alert; never
  auto-deleted.

### E. Intake abuse layers still missing (7.16.3)
- "Ignored mail" list data for the tenant (from `intake_rejections`).
- Sender match against buyers (address or domain) counts as known, closing D-031.
- Address rotation (Console action on the tenant page): new token; old row
  goes to `grace` with `grace_ends_at`; the router returns the "address has
  changed" auto-reply for grace addresses instead of a 404; a sweep retires
  them; lifecycle event logged; owner emailed the new address.
- Strict allowlist mode: opt-in per tenant from the Console, with an
  explanation of what it blocks. Never the default.

### F. Screens
- **Console:** per-tenant quarantine list (sender, subject, auth results, file
  types, hashes, reason), bulk release, bulk clear with type-to-confirm,
  rotate-address button, strict-mode toggle. Each request writes `admin_actions`.
- **Tenant (minimal, per the agreed 5.8 split):** the API for "used / allowance",
  held count and plain-English reason, ignored mail; plus a basic banner and a
  "Held for review" list with release. The fuller tenant dashboard stays in 5.8.

### G. Error catalog
New codes (numbering to be confirmed against existing entries): allowance 80%,
allowance 100% (`LIM-002` per the spec), abuse-ceiling hold, cost-breaker hold,
held-and-reviewing auto-reply, address-changed auto-reply, quarantine-release
refusals (wrong role). Snapshot file `error_catalog.txt` changes and is
reviewed as a diff.

## Tests (the spec's four, plus what the gaps above require)

Spec-required:
1. 11 attachments → all 11 quarantined, nothing else.
2. 21 unknown-sender emails in an hour → the 21st quarantined; a known
   sender's email at the same moment is not.
3. Ceiling trip → next document quarantined, auto-reply sent, alert raised,
   in-flight documents complete.
4. Release → received order preserved; released documents then count.

Added:
5. Linked duplicates count once; test-batch, failed and quarantined never count.
6. Console and tenant usage numbers agree.
7. One email per threshold per month even if the threshold is crossed twice.
8. Role matrix: owner can release only the two allowed reasons; reviewer and
   viewer cannot release; cross-tenant release attempt is 404.
9. The gate applies to web upload as well as email; test batch is exempt.
10. Grace address auto-replies; retired address is a plain 404.
11. Strict mode off by default.
12. Nothing quarantined is ever enqueued to the model (assert on the queue).

Tooling: web tests for the new Console screen, and one Playwright drive of the
whole flow, per the standing "drive the real app" rule.

## Questions for the founder

1. **Daily cost ceiling.** No breaker exists, so someone has to pick numbers.
   Cost per document runs about $0.01 – $0.35, and Scale (3,000 a month) is
   roughly 100 documents a day, so a heavy day is around $35. Proposal:
   **$50 per tenant per day** and a token ceiling to match, as constants, with a
   per-tenant override later. Is $50 right?
2. **Test batch and the ceiling.** Proposal: the founder's setup test batch is
   exempt from the ceilings, as it is from metering. OK?
3. **Web uploads.** Proposal: the same gate applies to uploads, not only email.
   OK?
4. **Founder release past a tripped ceiling.** Proposal: allowed, because it is
   an explicit human act, and it is logged. Otherwise a release would just
   re-quarantine.
5. **Split with 5.8.** Confirm 5.7 ships the API, Console screens and a minimal
   tenant banner/held list, leaving the full tenant dashboard to 5.8.

## Founder answers (2026-09-23)

1. Daily cost ceiling: **$50 per tenant per day of estimated AI cost** (the
   per-document `est_cost_usd`). Token ceiling to match, chosen by me and shown
   in the constants. Both are constants, with a per-tenant override later.
2. The setup test batch is **exempt** from both ceilings.
3. The gate is **one check for both channels** (email and web upload). It counts
   documents, not emails. The per-email rules (10 attachments, 20 unknown
   senders an hour) stay as they are.
4. A founder release **is allowed while a ceiling is still tripped**; it is an
   explicit human act and is logged.
5. Split with 5.8 as proposed: 5.7 ships the API, Console screens and a minimal
   tenant banner and held list; the full tenant dashboard stays in 5.8.
