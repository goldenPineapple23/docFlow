# Walkthrough — Slice 5.6: Lifecycle (cancel, suspend, reactivate, delete)

Purpose: drive the real app once, by hand, before building 5.7 on top of it.
Tests pass, but every recent slice had a bug that only showed up in a browser.
About 20 minutes. Use a **throwaway tenant** (create one from the Console; name
it obviously fake, e.g. "Acme Test Lifecycle"). Never use a tenant you want to
keep: step 9 deletes it.

## Setup

1. Start all four processes (nothing auto-starts): API (port 8000), web (port
   3000), Celery worker, **Celery beat** (beat is what runs the suspend sweep).
   Commands are in `README.md` and in `SETUP.md`.
2. Browse via `localhost`, not `127.0.0.1`.
3. Sign in at `/login` as the founder, then go to `/admin`.
4. Migrations `0018`, `0019`, `0020` must already be applied to staging (they
   are, as of 2026-09-23).

## Checks

Write pass / fail / notes next to each. Anything odd, screenshot it.

**A. Get a live tenant to work on**
1. Create a fake tenant and take it through go-live (or use an existing fake
   live tenant). Go-live should put the Stripe subscription in `trialing`.
   - [ ] Tenant list shows the `trialing` badge.

**B. Cancel: the three reasons** (Tenant page → Lifecycle tab → Cancel tenant)
2. Choose **customer requested** on a tenant with a subscription.
   - [ ] The form shows an effective date and states the rule that produced it.
   - [ ] Trying to set a date *earlier* than the computed one is refused.
3. Choose **non-payment**.
   - [ ] The effective date is shown with its rule. If there is no past-due
         record, the form says so ("double-check before confirming").
4. Choose **for cause** with fewer than 20 characters of reason.
   - [ ] It refuses, with a clear message. With 20+ it accepts.
5. Confirm a cancellation.
   - [ ] Tenant becomes `cancelling`; everything still works for that tenant
         (intake, review, export).
   - [ ] A confirmation email is in the outbox (Console) stating the effective
         date and the deletion date.
   - [ ] Lifecycle tab / Audit tab show the event and the constants in effect.

**C. Suspend sweep**
6. Cancel a second throwaway tenant as **for cause** (effective immediately) and
   wait for the beat sweep (it runs every few minutes).
   - [ ] Tenant moves to `suspended`/`pending_deletion` on its own.
   - [ ] Intake is blocked: an upload returns a clear coded message, not a 404.
   - [ ] The owner can still log in, browse, and download an export.
   - [ ] In Stripe (test mode) the subscription is cancelled and any pending
         setup-fee item is gone.
   - [ ] Suspension email and pending-deletion reminder are in the outbox.

**D. Queues**
7. Open `/admin/lifecycle`.
   - [ ] The suspended tenant appears in the **Wind-down queue** with days
         remaining.
   - [ ] Nothing has been deleted automatically.

**E. Reactivate**
8. On the suspended tenant's Lifecycle tab, click **Reactivate**.
   - [ ] It is as easy to find and click as Cancel.
   - [ ] Tenant returns to `active`, `onboarding_status` unchanged, data intact.
   - [ ] A subscription exists again (no second trial).
   - [ ] A reactivation email is in the outbox.

**F. Delete (only on the throwaway tenant)**
9. Cancel a tenant again and make it "ready to delete" (backdate its deletion
   date in the database, as the tests do, or wait out the window).
   - [ ] It appears under **Ready to delete**.
   - [ ] The delete button requires typing the exact tenant name; a wrong name
         is refused.
   - [ ] After deletion the business data is gone, but the tenant row and its
         lifecycle history remain.

**G. Stripe webhook**
10. In Stripe test mode, change a subscription's status (or send a test event to
    `/webhooks/stripe`).
    - [ ] The tenant list badge updates without a page reload of Stripe.
    - [ ] A `past_due` event records the first-notice time once.

**H. Access control**
11. Sign in as a tenant owner (not the founder) and open `/admin/lifecycle`.
    - [ ] It is a 404, not a 403.
