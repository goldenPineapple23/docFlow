# Walkthrough — Slice 5.4: Buyer merge, learned rules, field settings

Purpose: the three screens you'll use to tune a customer after go-live. Merge
customers DocFlow flagged as look-alikes (it never merges on its own). See,
switch off and delete what DocFlow has learned. Choose which fields a
customer is checked on. About 25 minutes. No model calls.

## Before you start

- Phase 2 done: the CUP-12 → CUP-12X rule exists on Acme Test Distributor.
- 5.3 done: Acme Test UAT Supply is live, with its customer list loaded.
- Sign in as yourself.

---

## Part 1 — Possible duplicate customers (10 min)

The look-alike flag is raised when an order arrives. To get a fresh pair
without paying for model calls, seed one through the real buyer-matching
code. Copy Acme Test UAT Supply's id from its tenant page address, then from
the repo folder run:

```
apps\api\.venv\Scripts\python.exe scripts\seed_merge_demo.py <tenant id>
```

It adds three orders named `seed_merge_demo.txt` under the customers "Acme
Test Cafe, LLC", "Northwind Test Supply" and "Northwind Test Supply Co.".
They're marked as setup-batch orders, so they don't count towards anything.

1. Reload the tenant page. **Possible duplicate customers →** now says "N to
   decide" in amber.
2. Open it. **Expect:** "Possible duplicate customers — Acme Test UAT Supply",
   the explanation (DocFlow flags, never merges; approved orders keep the name
   they were approved with), and a card per pair. Each card shows both
   customers with Email, Account, Orders, Rules and Since, and a radio to
   choose which to **keep**.
   - **Expect** at least **Northwind Test Supply / Northwind Test Supply Co.**
     There may also be a pair with a customer from the imported list (e.g.
     Northwind Test Bakery). Note what appears; judge whether each is a
     sensible flag.
3. On the Northwind pair, keep **Northwind Test Supply Co.** (it has the
   email) → **Merge…**
   - **Expect** an amber box: "Merge 'Northwind Test Supply' into 'Northwind
     Test Supply Co.'? 1 order and 0 rules move… 'Northwind Test Supply' is
     kept on record as a merged name." Nothing has happened yet.
4. **Confirm merge**. **Expect:** "Merged … : 1 order and 0 rules moved." The
   card goes, and **Recent merges** lists it, by **DocFlow support**.
5. If there's another pair that is **not** the same company: **Not the same
   customer**. **Expect:** "Kept as two separate customers." It doesn't come
   back.
6. Tenant page → **Learned rules →**. **Expect** a new rule, **Customer name →
   customer**: when an order says "Northwind Test Supply", it means Northwind
   Test Supply Co. The merge taught DocFlow the old name.
7. Tenant → **Audit →**. **Expect** the merge in the trail, by you.

## Part 2 — Learned rules (7 min)

Open **Acme Test Distributor** → **Learned rules →**.

1. **Expect:** "Learned rules — Acme Test Distributor". The table columns are
   Rule, For (customer), When the order says, It means, Used, Confirmed by,
   Status.
2. Find Phase 2's rule. **Expect:**
   - **Rule:** Product wording → SKU; **for:** Bella's Coffee House
   - **When the order says:** "12oz Paper Cups (1000ct)"; **it means:**
     CUP-12X
   - **Used:** at least 2 (BCH-UAT-22 and the revised BCH-UAT-06)
   - **Confirmed by:** `walkthrough@example.test`, with a link to its source
     order, PO BCH-UAT-06
   - **Status:** On
3. **Show** → pick **Product wording → SKU**. **Expect** the list narrowed to
   that type. Back to **All rules**.
4. **Switch off** → status **Off**. A switched-off rule stops firing on the
   next order. Nothing already on an order changes, and a rule never
   overrides a person's edit.
5. **Switch on** again.
6. **Delete** → **Expect** a confirmation, **Delete it** or **Keep**. Click
   **Keep**. (Deleting is a soft delete, kept for audit, and the wording
   could be taught again from a review. Keep this rule: 5.10 doesn't need it,
   but it's evidence.)

## Part 3 — Field settings (8 min)

Stay on **Acme Test Distributor** (it has many orders still in review) →
**Field settings →**.

1. **Expect:** "Field settings — Acme Test Distributor", the explanation of
   **Required / Optional / Hidden**, and two tables, **Order details** and
   **Line items**, with a radio per setting. **PO number** and line
   **quantity** say "always required" and can't be changed.
2. Set **Payment terms** to **Hidden**, **Why** `walkthrough`. Leave the
   re-check box unticked. **Save new version**.
   - **Expect:** "Saved as version N." It's listed under **Versions** with you
     and the note.
3. As `walkthrough@example.test` (private window), open any Needs review
   order. **Expect:** no **Payment terms** field. Hidden means not shown and
   not checked; the value is still read and kept.
4. Back in the Console: **Order date** → **Required**, and tick **Check orders
   still awaiting review against the new settings…** → **Save new version**.
   - **Expect:** "Saved as version N+1. X orders still awaiting review were
     checked again."
5. As the reviewer, open **BCH-UAT-03** (a Phase 1 order with no date).
   **Expect** a new "A required field is missing" check for the order date,
   and a lower confidence. Open the approved **BCH-2291**: **no change**, since
   approved orders keep what they were approved with.
6. Put it back: **Payment terms** → **Optional**, **Order date** →
   **Optional**, re-check ticked, **Save new version**. **Expect** BCH-UAT-03's
   order-date check to be gone again.
