# Walkthrough — Slice 5.2: Catalog and customer-list import (onboarding Steps 4–5)

Purpose: load a prospect's catalog the way you will for real, messy file
first. The import must catch blank and duplicate SKUs before they reach
matching, let you fix rows in place, and on a re-upload retire missing SKUs,
never delete them. About 25 minutes. No model calls.

Continues from [5.1](5.1-console-foundations.md): tenant **Acme Test UAT
Supply** exists and its intake holds `1-clean-catalog.xlsx` and
`customer-list.csv`.

## Before you start

- Sign in as yourself → **Tenants** → **Acme Test UAT Supply**.
- The sample catalogs are in `DocFlow\catalog-samples\`:
  - `1-clean-catalog.xlsx`: 20 items, no problems.
  - `2-mistakes-catalog.csv`: different column names, plus a blank SKU, a
    duplicated SKU, a SKU with a hidden character, a row with no
    description, an over-long unit, and two SKUs sharing one description.
  - `3-mistakes-catalog.xlsx`: a short, different catalog.

---

## Part 1 — A messy file first (10 min)

1. Tenant page → **Catalog →**.
   - **Expect:** the heading **Catalog · Acme Test UAT Supply**: the tenant's
     name is always shown, so you can't import into the wrong one. Under
     **1. Choose the file**: "From the prospect's intake:" with a **Use …**
     button per staged file, and **Upload a CSV or Excel file…**.
2. **Upload a CSV or Excel file…** → `2-mistakes-catalog.csv`.
3. **2. Match the columns.** The file says `Product Name`, `Item #`, `U/M`,
   `Price`. **Expect** DocFlow to have guessed SKU ← `Item #` and Description
   ← `Product Name`, with required fields marked with a red *. Change anything
   it got wrong.
4. **3. Check the file.** **Expect** a list of findings, each **Must fix** or
   **Check**, with a count, what's wrong, what to do, and the row numbers.
   Look for at least:
   - rows with no SKU (the Pumpkin Spice row): **Must fix**
   - the same SKU more than once (CF-1001, the "reserve" row): **Must fix**
   - stray spaces or hidden characters in a SKU (HNY-01): trimmed for you,
     but reported
   - one description with several SKUs (12oz cups: CUP-12 and CUP-12B):
     **Check**, a warning, not a blocker
   - a row with no description, and a value that's too long (the "Case of 12
     bottles…" unit)
5. Under the report, the preview table shows rows with problems first. Red
   cells can be edited.
   - In the Pumpkin Spice row's SKU cell type `SY-0099` and click away.
     **Expect:** it re-checks. The cell turns amber with "File had: (blank)"
     and **Undo**. The blank-SKU finding goes.
   - Click **Undo**. **Expect** the blank back, and the finding back.
6. **4. What committing will do** shows counts: **New · Updated · Brought
   back · Unchanged · Retired**. With problems left, **Commit** is greyed out,
   next to "N problems to fix before committing."
7. **Discard this import**. Nothing was written to the catalog.

## Part 2 — The clean catalog (5 min)

1. Under **1. Choose the file**, click **Use 1-clean-catalog.xlsx**: the one
   staged at intake, so no upload needed.
2. **Expect:** columns matched (`SKU`, `Description`, `UOM`; UPC and Item ID
   are extras), **No problems found.**, and **New 20**.
3. **Commit**. **Expect:** a finished message with "20 new, 0 updated, 0
   brought back…", and an **Earlier imports** list with this file, its row
   counts and who committed it.
4. Back on the tenant page. **Expect** "onboarding: catalog loaded", and
   **Catalog →** says "loaded".

## Part 3 — Re-uploads are diffs, never deletions (5 min)

1. **Catalog →** → upload `3-mistakes-catalog.xlsx` (columns `Stock No.`,
   `Details`, `Pack Size`, `Supplier Ref`). Map SKU ← `Stock No.`,
   Description ← `Details`.
2. Look at **4. What committing will do**. **Expect:** a large **Retired**
   count, and the line "Not in this file, so retired (kept, never deleted):"
   listing the SKUs. A SKU missing from a new file is retired, never
   hard-deleted.
   - Findings also appear: this file has a numeric SKU written two ways
     (`1002` twice) and a blank SKU.
3. **Discard this import**. Don't commit it; 5.3 needs the clean catalog.
4. Upload `1-clean-catalog.xlsx` again from your disk.
   - **Expect:** the columns already matched from last time (the mapping is
     remembered per tenant), and **Unchanged 20**, New 0.
   - **Discard this import**.

## Part 4 — Step 5: The customer list, which is optional (5 min)

1. Tenant page → **Customer list →**.
   - **Expect:** **Customer list · Acme Test UAT Supply** and the intro
     "Optional: customers are also created automatically from their first
     purchase order. Near-duplicate names are flagged for you to merge, never
     merged automatically."
2. **Use customer-list.csv**. Map the name to `Customer Name`, the account
   number to `Account No`, and email to `Email` (one row has none; that's
   fine).
3. **Expect** **New 4**, no blockers. **Commit**.
4. Judge the skippable framing: on the tenant page, **Customer list →** says
   "optional". Would you know you could skip it?
